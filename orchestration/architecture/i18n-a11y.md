# i18n And Accessibility

## i18n

Assumption: Spanish is the default UI language because the product specification is Spanish. English can be added later through dictionaries only.

Rules:

- No hard-coded user-facing strings in components.
- Keep dictionaries in `apps/web/src/i18n`.
- Use stable keys by feature, such as `drive.rename`, `photos.favorite`, `search.indexing`.
- Write Spanish with full orthography (accents, `¿?`, `¡!`) and sentence case; voice rules live in `design-system/brand.md` §2.
- Backend error codes are stable English identifiers; frontend maps them to localized text.

## Accessibility

- All controls must be keyboard reachable.
- Visible focus states are mandatory (`focus-ring` utility).
- Text contrast is at least 4.5:1 in both light and dark themes.
- Icon-only buttons require accessible labels and tooltips.
- Menus, dialogs, lightbox, and context menus must handle escape, focus trap, and return focus.
- Upload drag/drop must also support keyboard/file-picker operation.
- Search results must expose names, type, and match reason to screen readers.
- Use semantic landmarks: sidebar/nav, header/search, main, status.

## Responsive Behavior

- Desktop is primary, but UI must remain usable on tablet/mobile widths.
- Sidebar may collapse; search remains accessible.
- Virtualized grids/lists must maintain stable item sizes.
