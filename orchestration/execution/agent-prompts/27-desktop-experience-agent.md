## Deliver

1. **Device wrapping key**: on first launch generate 32 random bytes, store in the secure store under a reserved internal key (not a settings key), and pass `BENTO_DEVICE_WRAPPING_KEY` (base64url, no padding) to API and worker env. If secure storage is unavailable, do not pass it (backend falls back to a `0600` file) and expose `secureStorage: "os" | "file"` in platform metadata.
2. **Build configuration**: read `resources/build-config.json` (generated at package time from env `BENTO_TELEGRAM_API_ID`, `BENTO_TELEGRAM_API_HASH`, `BENTO_RELAY_URL`, `BENTO_PUBLIC_SITE_URL`; absent values omitted) and pass them to sidecars as env. Dev mode reads the same env vars from the parent process. Dev convenience: `BENTO_DEV_STORAGE_BACKEND=fake` forwards `STORAGE_BACKEND=fake` in unpackaged runs only. Update workflows to write the file from secrets/vars without echoing them.
3. **Remove Bot API remnants**: telegram secret keys from `SECRET_SETTING_KEYS`/`SECRET_ENVIRONMENT`, `bento_encryption_key`, any `telegram-bot-api` sidecar logic, validation entries, and tests. Existing stored legacy secrets are deleted on startup migration without logging values.
4. **Tray / menu bar**: icon variants (idle, syncing/uploading, paused, attention) generated by the existing icon script or committed small PNG/template images; menu with status line (from `GET /api/activity` polled every 5 s through the authenticated loopback client, paused while the system sleeps), `Abrir Bento`, `Pausar respaldo`/`Reanudar respaldo` (`PATCH /api/backup/policy`), `Salir`. Spanish labels by default with an English table selected from the OS locale (main process cannot use the renderer dictionary; keep a small typed table in `src/main/i18n.ts`).
5. **Background lifecycle**: closing the window hides it (preference `keepRunningInBackground`, default true); first hide shows a one-time notification "Bento sigue funcionando en segundo plano". `Salir` and OS shutdown quit cleanly through the existing sidecar shutdown. macOS: hide dock icon only while the window is closed.
6. **Launch at login**: preference default true after onboarding completes (renderer calls the bridge); macOS/Windows via `setLoginItemSettings`, Linux via `~/.config/autostart/bento.desktop` written atomically; `--hidden` argument starts in tray.
7. **Notifications**: native notifications only for new `attention` items from `/api/activity` (deduplicated by id) and for "N archivos añadidos a Bento" after Send-to uploads; clicking focuses the window and routes the renderer (`bento.onNavigate`).
8. **Deep links**: register `bento://`; accept only `bento://join?v=1&c=<code>` (strict regex `^[0-9A-HJKMNP-TV-Z]{4}-[0-9A-HJKMNP-TV-Z]{4}-[0-9A-HJKMNP-TV-Z]{4}$` after upper-casing); deliver to the renderer as `{kind: "join", code}` via `bento.onDeepLink`, buffering until the renderer subscribes. Handle macOS `open-url`, Windows/Linux `second-instance` argv and cold-start argv. Packaging: Forge `protocols`, deb desktop entry `MimeType=x-scheme-handler/bento;`.
9. **Send to Bento**: files passed via `open-file` (macOS) or argv/`second-instance` (Windows/Linux) are validated (regular files, no directories, no symlink escapes, max 2,000 per batch) and uploaded by main to `POST /api/assets/upload` with streaming multipart through the authenticated loopback client; progress is reflected by `/api/activity`. Windows: create a Send To shortcut on install/update and remove it on uninstall (Squirrel events). Linux deb: desktop entry `%F` + `MimeType` for common image/video/document types. macOS: `CFBundleDocumentTypes` with `LSHandlerRank` `Alternate` for `public.data`.
10. **Power**: `powerMonitor` on-battery/on-ac and initial state → `POST /api/backup/power`.
11. **PDF saving**: bridge `savePageAsPdf({suggestedName})` — main validates the sender is the main window, calls `printToPDF({printBackground: true, pageSize: "A4"})`, shows a save dialog (default `Documents/Kit de recuperación de Bento.pdf`), writes atomically. Renderer never supplies HTML or paths.
12. **Updates**: periodic metadata check (startup + every 6 h); when an update is available, download and verify automatically in the background (preference `autoDownloadUpdates`, default true); emit `ready` state; installation stays an explicit "Reiniciar para actualizar" action. Keep every existing verification and fail-closed rule.
13. **Bridge additions** (typed in `src/shared/contracts.ts`, validated in main, exposed in preload, documented in the new doc): `preferences.get()/set(partial)` for `keepRunningInBackground`, `launchAtLogin`, `autoDownloadUpdates`; `onDeepLink`; `onNavigate`; `savePageAsPdf`; `platform()` gains `secureStorage` and `locale`.
